# bookkit

> جعبه‌ابزاری برای کتاب‌های PDF اسکن‌شده: متن با چیدمان درست، Markdown، استخراج تمرین‌ها،
> گزارش کیفیت OCR، و «برش تصویر» برای دیدن چیزی که OCR خراب کرده.

ساخته‌شده برای همین مخزن (`Chapter1.pdf` — فصل اول یک کتاب ترکیبیات)، ولی روی هر
کتاب اسکن‌شدهٔ دیگری هم کار می‌کند.

نویسنده: ایجنت کدنویس Arena — این ابزار اولین مصرف‌کنندهٔ خودش است.

---

## چرا این ابزار؟

چالش کتاب اسکن‌شده این است: صفحه یک **تصویر ۴۰۰dpi** است به‌همراه یک **لایهٔ متن OCR**
که هیچ‌وقت شکست را اعلام نمی‌کند. نمونه‌های واقعی از همین فایل:

| روی کاغذ (پیکسل) | چیزی که OCR می‌دهد |
|---|---|
| $3\frac{2}{3},\;4\frac{1}{3},\;5,\;5\frac{2}{3},\dots,26\frac{1}{3},27?$ | `3, 4월, 5, 50.... 26 277` + `3층` |
| $n\times(n-1)\times(n-2)\times\cdots\times(n-r+1)$ | `nx (n-1) x (n - 2) x...x )и -r+2) x (n - r+1)` |
| پایان راه‌حل (مربع ☐) | `미` |

و بدتر: اسکنر به **هر کاراکتر یک اندازهٔ فونت تصادفی** داده، پس هیچ استنباطی بر پایهٔ
اندازهٔ فونت قابل اعتماد نیست. `bookkit` روی همین واقعیت بنا شده:

1. متن را با **آگاهی از چیدمان** بازسازی می‌کند (نه `get_text()` خام).
2. ساختار کتاب را از **الگو + هندسهٔ پیکسل** بیرون می‌کشد (کادرها، نوارها، سرفصل‌ها).
3. جای شک را **علامت می‌زند و هرگز بی‌سروصدا «تصحیح» نمی‌کند**، و یک برش با DPI بالا
   می‌دهد تا خودت (یا یک مدل بینایی) متن درست را از جوهر بخواند.
4. در پایان، اصلاحات را در مدل اعمال و خروجی را بازتولید می‌کند.

## نصب

```bash
pip install -e .          # یا: pip install pymupdf   و بعد  python -m bookkit
```

## استفادهٔ سریع

```bash
python -m bookkit info    Chapter1.pdf          # فراداده + سرشماری صفحه‌ها
python -m bookkit outline Chapter1.pdf          # فهرست تیترها با شمارهٔ صفحه
python -m bookkit text    Chapter1.pdf -p 6     # متن صفحهٔ ۶ با نقش هر پاراگراف
python -m bookkit items   Chapter1.pdf --kind problem exercise
python -m bookkit ocr     Chapter1.pdf --queue  # گزارش کیفیت + صف بازبینی
python -m bookkit md      Chapter1.pdf -o out/chapter1.md
python -m bookkit jsonl   Chapter1.pdf -o out/chunks.jsonl
python -m bookkit digest  Chapter1.pdf          # نقشهٔ فشرده برای context محدود
python -m bookkit serve   Chapter1.pdf          # رابط وب بازبینی
```

همهٔ دستورها `--json` دارند و خروجی‌شان قابل لوله‌کشی است.

### برش تصویر — سلاح مخفی

```bash
# ناحیهٔ مشکوک را با ۴۰۰dpi ببین
python -m bookkit crop Chapter1.pdf -p 6 --line 2 --dpi 400 -o line.png

# هر جای کتاب که یک رشته هست را برش بزن
python -m bookkit find Chapter1.pdf "Problem 1.7" -o crops/
```

### اصلاح با تأیید پیکسل

```bash
cat examples/repairs.jsonl
# {"page":6,"line":2,"before":"3, 4월, 5, 50.... 26 277",
#  "after":"3 2/3, 4 1/3, 5, 5 2/3, ..., 26 1/3, 27?","reason":"verified at 340 dpi"}

python -m bookkit fix Chapter1.pdf --repairs examples/repairs.jsonl \
    -o out/chapter1.fixed.md
```

امتیاز OCR همین کتاب با ۶ اصلاح تأییدشده از **۲۱۰ به ۱۸۰** رسید و
`script_mix` از ۱۲ به ۷ (۷ مورد باقی‌مانده متنی صحیح هستند: `АСBACBD` که برگردان
لاتین نام‌گذاری ترکیبیاتی است و فقط با حروف سیریلیک شبیه است).

## معماری

```
bookkit/
├── core.py       مدل صفحه: خطوط با bbox، پاراگراف‌های بازچینش‌شده، سرفصل/شمارهٔ صفحه‌ها
├── ink.py        هندسه از پیکسل: خطوط، کادرها، نوارهای پرشده (بدون وابستگی به OCR)
├── structure.py  نقش‌ها و آیتم‌ها: فصل/بخش/تمرین/مسئله/راه‌حل + زمینهٔ بخش
├── quality.py    تشخیص خطای OCR، صف بازبینی، چرخهٔ اصلاح
├── render.py     Markdown، chunk های JSONL، digest، payload وب
├── server.py     رابط وب (فقط کتابخانهٔ استاندارد) + API
├── web/index.html  UI فارسی/راست‌به‌چپ
└── cli.py        خط فرمان
```

### ۱. بازسازی متن (`core.py`)

* span های گلیف → خط: فاصله فقط جایی درج می‌شود که هندسه اقتضا کند (شکاف > ۰٫۳۴em)
* شکست پاراگراف از **شکاف عمودی + تورفتگی + پایان جمله + مرز بلوک**
* حذف سرصفحه/شمارهٔ صفحه بر اساس تکرار بین صفحه‌ها (مقایسهٔ نرمال‌شده تا لرزش OCR مشکلی نسازد)

### ۲. هندسه از پیکسل (`ink.py`) — بدون هیچ OCR

| چیزی که پیدا می‌شود | معیار |
|---|---|
| خط افقی | پهن (>۲۲٪ عرض)، **نازک** (≤۴px) و ایزوله (ردیف‌های بالا/پایین خلوت) |
| خط عمودی | چرخهٔ جوهر ≥ ۰٫۵ با شکاف‌های کوچک (≤۴px) — مرز یکپارچه یا خط‌چین |
| کادر | جفت خط افقی هم‌امتداد + **تأیید لبه** در دو سر (جوهر فقط داخل بازه) |
| نوار پرشده | چگالی جوهر ≥ ۰٫۸۵ *در بازهٔ خودش* — این معیار متن سفید روی نوار مشکی |
| | («Problems») را از متن معمولی جدا می‌کند |

نکتهٔ کلیدی: آستانهٔ سیاه/سفید روی **۲۰۰** تنظیم شده، چون مرزهای نازک در اسکن
خاکستری (≈۱۵۷) می‌شوند و با آستانهٔ رایج ۱۵۰ کامل ناپدید می‌شوند.

### ۳. ساختار و آیتم‌ها (`structure.py`)

* نقش‌ها: `heading` (سطح ۰/۱/۲/۳)، `problem`، `exercise`، `solution`، `example`، `label`، `body`
* تفکیک «۱٫۶ Summary» (تیتر) از «۱٫۳۶ Which integers n satisfy…?» (تمرین) با آزمون
  **شکلِ عنوان**: کوتاه، بدون نقطه‌گذاری، اکثر کلمات با حرف بزرگ
* تشخیص «adversarial» سرصفحه‌های تکرارشونده با `1.2. COUNTING LISTS OF NUMBERS`
  و جایگزینی‌شان با تیتر واقعی همان بخش
* ادغام ادامهٔ پاراگراف: مسئلهٔ داخل کادر فقط تا وقتی ادامه می‌گیرد که در **همان کادر**
  بماند؛ بیرون کادر با قواعد تورفتگی/حرف کوچک/پایان جمله
* پرچم `duplicate_of` برای مسئله‌هایی که در متن دوباره تکرار می‌شوند (مثل مسئلهٔ ۱٫۷)

### ۴. کیفیت OCR (`quality.py`)

| کد | معنا |
|---|---|
| `script_mix` | گلیف چینی/کره‌ای/سیریلیک در متنی لاتین — امضای خطای ناحیهٔ فرمول |
| `span_outlier` | یک گلیف ~۲ برابر اندازهٔ متن: نشانهٔ چسبیدن دو عدد |
| `math_line` | خطی که فرمول به نظر می‌رسد — کسرهای تخت‌شده فقط با پیکسل حل می‌شوند |
| `glued_words` | `wordWord` — فاصلهٔ گم‌شده |
| `empty_region` | باند خالی بزرگ: شکل یا جدول (در متن دیده نمی‌شود) |
| `low_text_page` / `missing_text_layer` | صفحه‌ای که چیدمانش خوانده نشده |
| `unreliable_metrics` | اندازهٔ گلیف‌ها درون هر خط پخش زیادی دارد → اندازهٔ فونت قابل اعتماد نیست |

خروجی: امتیاز هر صفحه، верdict (clean/review/suspect/broken) و **صف بازبینی** با bbox
و راهنمای اقدام برای هر مورد.

## رابط وب

```bash
python -m bookkit serve Chapter1.pdf --port 8765
```

* فهرست صفحه‌ها با رنگ وضعیت (سبز/زرد/قرمز)
* نسخهٔ تصویری صفحه + **کادرهای تشخیص‌داده‌شده روی آن** (خطای OCR قرمز، کادر سبز، نوار بنفش)
* برای هر خطای OCR: متن فعلی، برش ۳۰۰dpi از پیکسل، و کادر ورود متن درست → `POST /api/repair`
* دکمه‌های خروجی: Markdown / JSON / JSONL / گزارش OCR (ذخیره در پوشهٔ خروجی)

API: `/api/book`، `/api/page/<n>`، `/api/page/<n>.png`، `/api/crop/<n>.png?line=…|bbox=…`،
`/api/repairs`، `/api/rescan`، `/export/<kind>`.

## چه چیزهایی عمداً انجام **نمی‌شود**

* OCR مجدد نمی‌زند و متن را «حدس نمی‌زند» — فقط علامت می‌زند و پیکسل می‌دهد.
* ریاضی را بازسازی نمی‌کند (کسرهای تودرتو): یک برش با DPI بالا و یک فرم ASCII ساده
  می‌دهد؛ تبدیل به LaTeX کار مرحلهٔ بعد است (خروجی `jsonl` برای همین ساخته شده).
* به سرویس بیرونی وابسته نیست: تنها وابستگی `pymupdf` است.
